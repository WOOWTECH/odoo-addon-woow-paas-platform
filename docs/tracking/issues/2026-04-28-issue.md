## 1. Skip Trial 對話框未揭露稅金（金額預告 vs 實扣不一致）

- **位置**：Service Detail → Skip Trial 確認對話框
- **現況**：對話框寫「Generate your first invoice of **499 pts**」
- **實際**：扣款 **573.85 pts**（含 15% 稅）
  - Untaxed: 499.00
  - Tax (15%): 74.85
  - Total: 573.85 pts
- **影響**：使用者看到 499 點同意 → 實扣多 75 點，類似隱藏費用觀感
- **建議**：對話框改顯示「499 pts (excl. tax) → 573.85 pts (incl. 15% tax)」或同時揭露未稅/含稅金額

## 2. Invoice 金額顯示不一致（精度差異）

- **同一張 INV/2026/00005，多處顯示不同精度**：
  | 位置 | 顯示 |
  |---|---|
  | Billing 主頁 → Recent Invoices | **574 pts**（四捨五入） |
  | Billing → Invoices 列表 | **574 pts**（四捨五入） |
  | Billing → Invoice Detail（總額） | **574 Points**（四捨五入） |
  | Billing → Invoice Detail（小計區） | **573.85 pts**（兩位小數）|
- **影響**：同一發票出現 574 vs 573.85 兩種金額，使用者會懷疑是不是被重複扣款 / 算錯
- **建議**：全站統一顯示精度（建議都用 573.85 pts 兩位小數，含稅金額需精確）
- **註**：Wallet 交易紀錄是 $573.85，後端值正確，僅前端 invoice 顯示被四捨五入

## 3. 點數單位顯示混亂（$ / pts / Points / NT$ / Credits 五種寫法）

- **位置**：整個 Billing 區域
- **現況**：同一筆點數在不同位置用不同寫法
  | 顯示 | 位置 |
  |---|---|
  | $576.15 | Header sidebar |
  | 576.15 Points | Credit Balance 卡片 |
  | $573.85（扣款，無負號）/ +$1,100.00 / +$50.00 | Credit Point History 交易明細 |
  | 574 pts | Invoice 卡片 / List |
  | NT$ 1000 Credits | Top-up 描述 |
  | 1 Point = NT$ 1 | Conversion rate 提示 |
- **影響**：
  - $ 容易被誤認成美金（實際是與 NT$ 等值的點數）
  - 同一個值出現 "$576.15" 與 "576.15 Points" 兩種寫法，使用者要心算才能對應
- **建議**：全站統一單位用 `pts` 或 `Points`，移除 `$` 前綴；Top-up 流程明確標示「NT$ X → Y pts」

## 4. Top-up Bonus 規則只在採購頁顯示，事後紀錄／收據未揭露

- **位置**：Credit Point History / Transaction History
- **現況**：
  - Top-up Store 採購頁有完整級距表（50→0 / 100→+5 / 500→+30 / 1000→+100），規則本身**有揭露**
  - 但 History 描述只寫「Top-up: NT$ 1000 Credits」，**不帶 bonus 資訊**
  - 使用者只看到 +$1,100 不知道為什麼 NT$1000 變 1,100 點
- **影響**：
  - 加值後沒有任何「+100 bonus」字樣留存，事後無法稽核
  - 與 NT$ 50 Credits → +$50 對比時會懷疑是不是算錯
- **建議**：
  - History 描述明確顯示 base + bonus（如「Top-up: NT$ 1000 + 100 bonus = 1,100 pts」）
  - 對應 invoice / receipt 應一併標示 bonus

## 5. 🐛 [BUG] Subscription List → Manage 按鈕拋 TypeError，無法開啟訂閱詳細

- **位置**：Billing → Subscriptions（`#/billing/subscriptions`）→ SUB-00001 卡片的 Manage 按鈕
- **現象**：點擊 Manage 按鈕沒有反應，Modal 不會開啟
- **Console error**：
  ```
  TypeError: Cannot read properties of undefined (reading 'stopPropagation')
      at SubscriptionListPage.showManage
      at Object.onClick (...)
      at WoowButton.handleClick (...)
  ```
- **根因推測**：`SubscriptionListPage.showManage` 內呼叫 `ev.stopPropagation()`，但 `WoowButton` 元件的 onClick 沒有把 native event 傳遞下來 → ev = undefined
- **影響**：使用者無法檢視訂閱詳細 / 取消訂閱 / 修改方案 — 功能性阻塞
- **建議修法**（任一）：
  1. `showManage` 改為 `showManage(ev) { ev?.stopPropagation(); ... }`（容錯）
  2. `WoowButton` 元件統一將原生 event 透過 onClick 傳給呼叫方
  3. 改用 stop modifier（如 OWL 的 `t-on-click.stop`）取代手動呼叫
- **Update 2026-04-28**: G5-A hotfix 上 commit `e761929`（SubscriptionListPage `showManage` / `showCancel` 容錯）。Code review 同時找到 **6 個其他 call sites 有相同 bug pattern**（`WoowButton onClick → ev.stopPropagation()` 但 ev=undefined）：
  - `src/static/src/paas/pages/billing/InvoiceListPage.js:137` — Pay 按鈕（高機率使用者會 crash）
  - `src/static/src/paas/components/marketplace/AppCard.js:85`
  - `src/static/src/paas/components/smart-home/SmartHomeCard.js:78`
  - `src/static/src/paas/components/service-card/ServiceCard.js:95`、`:105`、`:113`
  - 建議：開 fast-follow PR 用同樣 `?.` patch 修這 6 處，或等 sprint 2 G5-B 結構修法統一處理

## 6. 扣款交易未明確標示負號

- **現況**：
  | 類型 | 顯示 |
  |---|---|
  | 加值（Top-up） | **+$1,100.00** / **+$50.00**（有 `+`） |
  | 扣款（Subscription invoice） | **$573.85**（無正負號）|

  - `arrow_outward` icon 雖有但小、不顯眼
  - 類型一致性差，使用者要逐筆心算才能分辨「進」與「出」
- **建議**：扣款明確顯示 `-$573.85`（含負號 + 紅色或不同顏色），與 `+` 號加值對稱

## 7. Top-up Store「BEST VALUE」標籤標在錯誤方案上

- **位置**：Top-up Store（`#/billing/topup`）
- **現況**：4 個方案的 bonus 比例
  | Pack | Bonus | Bonus % | 標籤 |
  |---|---|---|---|
  | 50 Credits | — | 0% | — |
  | 100 Credits | +5 | **5%** | **BEST VALUE** ❌ |
  | 500 Credits | +30 | 6% | — |
  | 1,000 Credits | +100 | **10%** | — ❌ |
- **影響**：
  - 1,000 Credits 才是真 best value（10% bonus），標籤誤導使用者選次佳方案
  - 客單價降低，且讓懂計算的使用者懷疑系統公信力
- **建議**：
  - 「BEST VALUE」改貼到 1,000 Credits（最高 bonus %）
  - 或改用非比較性標籤（如 "POPULAR" / "MOST PURCHASED"）

## 8. Unknown route 不顯示 404，悄悄落回 Dashboard
