**真正根因（第三方 addon `sh_subscription_wallet/models/subscription.py` 兩支 cron 疊加，非本 repo）**：
- `_cron_wallet_charge`（daily）：`next_payment == today` 才扣，**扣完不推進 next_payment**（且用等值比對）。
- `_cron_wallet_charge_retry`（hourly）：撈 24h 內 `state='failed'` 的 deduct 交易重試；`_process_wallet_payment`（`subscription_wallet_mixin.py`）失敗時 `savepoint.rollback()` 後**又 create 一筆新 `state='failed'`（create_date=now）** → 24h 窗永遠有剛產生的 failed → **窗永不過期→每小時無限重試**，failed 列指數膨脹。

**修法方向（強線索，session 內另發現）**：本 repo fix 層 `src/models/sh_subscription_fix.py` 已有 **dunning-aware 的 `_sh_create_auto_invoice`**（`next_payment <= today` 篩、成功才推進、threshold 後 auto-cancel）——與上游那兩支 wallet cron **並存冗餘**。故修法傾向**停用/覆寫上游 `_cron_wallet_charge` + `_cron_wallet_charge_retry`**（讓 fix 層 invoice cron 當唯一計費路徑），或至少讓 retry 收斂（回寫舊 failed 狀態＋每訂閱重試上限）＋成功扣款推進 next_payment。TDD：失敗訂閱重試 N 次停、成功後 next_payment +1 週期、有餘額一週期只扣一次。stg 清理：832 筆 failed 垃圾＋9 張訂閱 next_payment 校正。
