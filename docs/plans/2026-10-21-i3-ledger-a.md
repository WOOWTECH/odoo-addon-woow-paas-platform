## Review boundaries and operational gaps

- The dispatch timestamp grants one worker entry **before prechecks**. It is not an HTTP sent receipt. Duplicate entry does no GET, POST, retry classification, event settlement or latch reset. A crash after entry leaves the order for verification/review.
- Worker and void completion require the same durable UUID/owner/event/target/quota plus the existing live lease and verifier fence. Verifier claims carry the UUID and exact event. Pre-upgrade orders with no ledger history keep the legacy verifier path; missing/mismatched rows on orders with ledger history fail closed. No UUID backfill.
- A durable attempt cannot be automatically requeued by the verifier from quiet balance/absence of an outcome: it goes to `needs_review` with the existing evidence-conflict code. Only the worker's established definite no-execution paths can create a subsequent attempt. All prior identities and latches remain.
- No client metadata or audit correlation is enabled. There is no local assertion of remote store ownership or epoch. Owner binding, restore governance and final retention require Elmo decisions before later slices can treat these identities as correlation authority. No deletion/prune job is introduced; event cleanup does not delete scalar reservation references.
- This model is immutable through Odoo, including sudo ORM mutation; the private issuance capability is a Python object, never a serialized context flag. SQL constraints enforce canonical UUIDv4, uniqueness and positive snapshots. Database superuser tampering is outside the Odoo ACL boundary.
- Ordinary PR version remains `18.0.1.0.252`, with no migration directory. A normal module upgrade is required to create the additive table/constraints/ACL before running the worker. No upgrade/deployment was executed here. App rollback must retain ledger data and stop incompatible workers; do not drop the table or clear latches to recover availability.
- This bounds local entry only. A process paused after the final pre-POST read can still wake late; this slice adds stale result fences and conservative requeue, not a remote fencing token or an exactly-once guarantee. Missing upstream receipts keep existing uncertainty. I3 remains incomplete.
