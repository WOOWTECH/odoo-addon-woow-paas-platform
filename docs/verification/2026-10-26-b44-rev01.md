## Change

The bounded origin gate now persists a redacted policy-denial receipt only
after the assertion has passed RS256 signature, issuer, audience, expiry,
required-claim, and `type=app` validation, and the signed email is absent from
the fresh committed allowlist. The receipt contains the exact journal
generation/effect/desired digest, first observation time, and a SHA-256 digest
of the signed session-cohort fields. It never stores a cookie, JWT, email,
subject, or identity nonce.

Repeated requests from the same cohort are idempotent. A stale envelope cannot
write a receipt after a newer close. Existing latch volumes receive only an
additive table migration; the high-water row is neither recreated nor reset.
A fresh gate process reads the same receipt and still starts closed. The mTLS
control endpoint exposes exact-envelope receipt readback with
`release_permitted=false`.

The receipt intentionally does **not** clear `access_token_revoke_pending`,
activate a gate, or claim Cloudflare token-revocation completion. A later
normal-product finalizer still needs an independently authorized contract that
binds the intended pre-existing Cloudflare session cohort to this receipt.
