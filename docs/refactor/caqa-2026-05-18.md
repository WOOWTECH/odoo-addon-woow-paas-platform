## Caveat 清單（給 leader 決定是否帶入 reviewer）

### C1 — Cleanup hook `mapped` 路徑建議 belt-and-braces 加 `sudo()` 〔medium〕

**Location**: `src/models/cloud_service.py:1134-1136`

**現狀**:
```python
user_mcps = self.project_ids.mapped('mcp_server_ids').filtered(
    lambda s: s.scope == 'user'
)
if user_mcps:
    user_mcps.sudo().unlink()
```

`mapped('mcp_server_ids')` 走 ir.rule（如果 caller context 不是 sudo）。
- 目前 caller 都是 cron / subscription_lifecycle_mixin，預期都是 sudo
- 但 `_do_cleanup` 是 public method，未來 callable surface 擴大時可能有 non-sudo caller

**風險**:
- 若 caller 是 user-context（非 sudo），且該 user 對某些 user-scope MCP 沒 read 權限（cross-workspace），`mapped` 會漏掉那些 row → 沒 unlink → 變 zombie
- 雖然 ACL chain 設計上不會讓 cross-workspace user 看到別人的 MCP，但 service `_do_cleanup` 是 service-owner 的操作，理論上 service 屬於 user 的 workspace，user 應該能看到所有自家 user-scope MCP — 但這個 ACL evaluation 是 belt 不是 braces

**建議方向**（給 implementation phase 選一個）:
- A: `self.project_ids.mapped('mcp_server_ids').sudo().filtered(...).unlink()` — sudo mapped 結果
- B: `self.sudo().project_ids.mapped('mcp_server_ids').filtered(...).sudo().unlink()` — sudo 整條 walk

不擋 verdict。Leader 判斷是否要求在 reviewer phase 內補上、或留 follow-up。

### Caveat 整體層級
