# Task: Debug 並修復 Odoo admin 帳密 bug

## Description

使用者在 PaaS UI 建立 Odoo 服務時填入 Administrator Email / Password，但部署後仍為 admin/admin。需要追蹤完整的 value 傳遞鏈確認根因，並實作修復。

## Acceptance Criteria

- [ ] 確認 `odooPassword` 值正確存入 `CloudService.helm_values` JSON 欄位
- [ ] 確認 PaaS Operator 收到的 Helm values 包含正確的 `odooPassword`
- [ ] 確認 Bitnami chart 收到 values 後的實際行為（建立新使用者 vs 取代 admin）
- [ ] 修復後部署 Odoo，可用自訂 email/password 登入
- [ ] 預設的 admin/admin 不可用或密碼已變更

## Technical Details

### 調查步驟

1. **檢查已部署 service 的 helm_values**：
   ```sql
   SELECT helm_values FROM woow_paas_platform_cloud_service WHERE template_id = (SELECT id FROM woow_paas_platform_cloud_app_template WHERE slug = 'odoo') ORDER BY id DESC LIMIT 1;
   ```
   確認 JSON 中是否有 `odooPassword` key 及其值。

2. **檢查 PaaS Operator 日誌**：確認 operator 收到的 values 是否包含 `odooPassword`。

3. **檢查 Helm release values**：
   ```bash
   helm get values <release-name> -n <namespace>
   ```
   確認 `odooPassword` 是否存在於 release values。

4. **研究 Bitnami Odoo entrypoint**：
   - Bitnami 的 `/opt/bitnami/scripts/odoo/entrypoint.sh` 和 `setup.sh` 如何處理 `ODOO_EMAIL` 和 `ODOO_PASSWORD` 環境變數
   - 確認是建立新使用者還是修改 admin 帳號

### 可能修復方案

**方案 A**（若 Bitnami 建立獨立使用者）：
在 `helm_default_values` 中加入 `customPostInitScripts` 來修改/停用 admin 帳號：
```yaml
customPostInitScripts:
  disable-admin.sh: |
    #!/bin/bash
    # 修改 admin 帳號密碼或停用
```

**方案 B**（若 values 傳遞有問題）：
修復 value 傳遞邏輯中的 bug。

### 涉及檔案

- `src/controllers/paas.py` — value 傳遞邏輯（可能需修改）
- `src/data/cloud_app_templates.xml` — helm_default_values（可能需加入 customPostInitScripts）
